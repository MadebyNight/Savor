# V1.1.2 交互一致性修复

日期：2026-09-20。状态：交互修复与开发者配置已完成，最终 APK 已同签名覆盖安装并通过真机验收，版本变更归档至 Git。

## 目标与范围

沿用米白、暖黄、灰绿的现有品牌风格，修复全局控件的交互样式冲突。覆盖点单、冰箱、采购清单、周菜单、菜谱、设置与业务弹窗；系统相机、相册、文件选择和权限界面保持 Android 原生行为。业务规则、数据库及凭据存储不变。

版本：npm / Android versionName `1.1.2`；Android versionCode 从 `2` 递增为 `3`。交付同包名、原调试签名 APK；不自动发布到远程仓库。

## 排查结论与验收标准

| 问题 | 原因 | 修复与验收标准 |
| --- | --- | --- |
| 自动同步复选框巨大且亮蓝 | 通用输入框宽高覆盖 checkbox，未配置 accent | 20px 灰绿勾选框，整行标签至少 48px 可点；不影响文字输入框 |
| 普通按钮无按下反馈 | 仅定义 hover，触摸高亮被禁用 | 所有可用按钮都有轻微明暗反馈；hover 仅用于精确鼠标设备；禁用状态不反馈 |
| 次要按钮出现深色外圈 | `.outline` 与框架工具类重名 | 消除非焦点 outline，保留浅色边框和键盘焦点提示 |
| toast 鲜绿鲜红不统一 | Sonner richColors 默认配色 | 成功灰绿、错误柔和红、警告暖黄，保留文字和状态图标 |
| 弹窗缩放失效 | 移动定位修复覆盖 transform 动画 | 底部面板轻微上移淡入、居中弹窗轻微缩放淡入；保留定位修复和减少动画支持 |
| 焦点圈重复且不一致 | 全局 outline 与组件 ring 叠加 | 共用单层灰绿焦点圈，输入框/select/summary 同步；搜索框保留内部焦点显示 |
| 关闭按钮过窄 | 图标工具类限定宽度，移动仅补高度 | 点击区域至少 48×48px，标题不与按钮重叠 |

## 补充需求：开发者配置

用户要求在 AI 配置下方增加开发者配置按钮，启用时输入指定密码。配置包含 URL、模型与 API Key。

用户明确选择：不部署服务端，将整套配置加密后内置于受控分发 APK；其他手机输入指定密码即可启用。这是对原“不在 APK 固定配置存放 Key”规则的本次明确例外，仅允许密文；源码、日志、测试与 Git 均不得包含真实 Key。

- 使用 PBKDF2-SHA256（600,000 次迭代、随机盐）派生 AES-256-GCM 密钥；随机 IV、认证标签和固定格式标记用于校验完整性。密码不写入客户端源码。
- 当前手机内完成读取与加密，只导出密文到忽略文件 `public/developer-ai-profile.json`。Vite 原样复制到 APK；该文件必须由维护者单独保管，不能从 Git 恢复。
- 正确密码解锁后，配置存入独立的 Keystore 加密槽；个人 URL、模型和 Key 不被覆盖。关闭后清除开发者槽并恢复个人配置，再次启用需重新输入密码。Android 重启保持启用状态，浏览器预览只保留到页面会话结束。
- 错误密码、取消和损坏密文均不修改现有配置、不发 AI 请求。解锁不自动执行连接测试；识别前仍需确认发送。
- 受控分发假设：APK 持有人可离线猜测密码；已知密码的人可以提取共享 Key。该方案不提供服务端撤销或逐设备额度控制；撤销共享凭据需在 AI 服务商轮换 Key 并重新打包。
- 新增解密与请求路由单测、模拟包 UI 回归，最后验证真实设备解锁、重启、关闭恢复与 APK 无明文凭据。

### 后续打包与更新

保持手机已打开、当前个人 AI 配置完整，先运行日志采集，再执行：

```powershell
python scripts/export-developer-profile.py --serial <设备序列号>
```

脚本交互读取密码并仅导出密文；已存在文件时拒绝覆盖，确认轮换配置后加 `--replace`。然后按常规 build → cap sync → Android 构建流程打包。不要把密文、密码或 Key 添加到 Git；密文丢失时必须重新生成。没有该文件的安装包仍可使用个人 AI 配置，点击开发者入口会明确提示缺少内置配置。

真机回归（要求原先未启用开发者配置，结束后仍关闭）：

```powershell
python tests/android_developer_ai.py --serial <设备序列号>
```
