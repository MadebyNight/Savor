# 食光 · 开发规划

v0.4 · 2026-09-18

## 目标、架构、技术栈

完成产品需求确认中的 MVP；沿用 React + Vite 高保真界面，以 Capacitor 交付 Android APK。原生 SQLite 表保存带版本的结构化 JSON 状态，私有文件目录保存图片；SharedPreferences 保存普通偏好；Keystore AES-GCM 保存凭据。此 JSON 聚合存储方案降低个人应用迁移与整包同步复杂度，仍使用 SQLite 事务保证状态写入原子性。

热量全部移除、小红书自动获取暂缓。安全限于必要凭据保护、输入校验与不静默覆盖，不建设账号、审计或专项渗透体系。

## 实施任务与目标文件

1. 文档收口：docs/产品需求确认.md、docs/开发规划.md、docs/设计逻辑.md、AGENTS.md、README.md。以已确认规则为目标，原型只作为视觉及未明确细节的依据。
2. 核心前端：src/App.jsx、src/data.js、src/styles.css；移除热量、菜谱维护、图片、采购快照、真实日期和餐次份数、历史复制、库存日期与缺口。检查构建及业务测试。
3. 本地数据：src/storage.js、原生 LocalDataPlugin.java 和 MainActivity.java；SQLite/图片/偏好/凭据/原生网络，持久化失败必须反馈。检查原生构建及重启保存。
4. AI 和设置：独立服务及组件，官方协议核验、内容发送确认、图文和小票草稿、逐项保存与失败取消。使用本地可控服务验证错误/成功，真实服务待用户凭据验证。
5. 备份与同步：独立服务及组件，导入校验、替换前备份、独立图片、版本冲突及恢复；用可控 WebDAV 服务验证冲突和中断，不把模拟服务等同坚果云真机验收。
6. 测试与发布：关键领域单元测试、浏览器及 Android E2E、npm run build → npx cap sync android → gradlew assembleDebug，验证 APK。docs/开发进度.md 记录证据及待介入事项，按可验证增量提交。

## 阶段完成标准

### 手机端布局接入

以 `docs/移动端改版方案.md` 的原型方向接入正式 React 应用：`src/App.jsx` 管理导航、分类及菜谱列表，`src/styles/mobile.css` 统一小屏和短横屏布局，`src/components/MobileWeek.jsx` 提供按日三餐和纵向总览。保留已有存储、采购、快照、历史复制与 AI 入口。

新增 `tests/e2e_mobile.py`，更新原核心、AI 和真机脚本的导航入口；验证首屏、四种视口、文本放大、搜索/分类、草稿、采购抵扣、按日排餐与快照。Android 按 build → cap sync → assembleDebug 验证，当前真机连接状态及证据记录在开发进度。

- 本地：离线五模块、重启保存、菜谱维护不破坏快照、真实周、备份与旧数据迁移。
- AI：文字与图片/小票可编辑草稿；失败可恢复；协议以实际官方能力为准，不再要求未定义的“两种协议”。
- 同步：手动确认采用居中弹窗；应用级同步控制器在本地加载完成后执行一次启动同步，可关闭。同步基线绑定服务器和账号；首次连接及双方变化必须确认，单端变化自动同步。恢复前检查本地状态是否变化，失败保留数据。保留 10 版备份和凭据保护。
- 发布：安装、重启、升级、离线及双设备流程，明确真实服务未验证项。不能以构建成功代替 E2E。

## 工作限制

系统返回由 `MainActivity` 的 AndroidX `OnBackPressedDispatcher` 分发可取消的 `shiguang:back` 事件，`src/useBackHandler.js` 按弹窗深度、优先级和打开顺序处理一层；未消费时执行系统默认返回。共用 Dialog、移动侧栏、设置/菜谱编辑、周总览接入，关闭确认框复用取消逻辑。`tests/e2e_back.py` 验证前端协议和状态保留；键盘、原生按键及返回手势须另做设备验收。

仅在当前工作区写文件和安装工具；不删除整个文件夹，不覆盖用户无关改动。缓存、SDK、JDK、测试临时输出留 .android-tools/ 或忽略目录。及时提交进度，只提交相关源文件，不提交凭据、SDK、node_modules、dist。

## AI 接口连接验证

- 设置页通过实际 Chat Completions 短文本请求验证配置，展示接口返回的模型与耗时；仅测试不写入配置或识别草稿。
- 覆盖输入 Key 优先、已保存 Key 回退、HTTP 错误、无效响应、取消和手机布局；停止等待后忽略迟到结果。真实服务连通性仍需在设备上使用有效凭据验证。
