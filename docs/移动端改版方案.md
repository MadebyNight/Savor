# 食光 · 手机端改版方案与第一版原型

2026-09-18 · 设计提案 / 待视觉验收

## 目标与依据

打开应用即可看到菜品分类和菜谱，让选菜、调整份数、查看采购和安排三餐适合手机操作。保留米白暖黄品牌色；采用用户偏好的常驻左侧分类，不照搬参考图片。

现有实现的问题：App.jsx 在菜品前叠加顶栏、英文标语、大标题、说明和欢迎横幅；styles.css 在手机上仍使用两列大图，图片高 125px，食材文字缩到 10px，加减按钮缩到 21–26px；主导航收进抽屉；周菜单保留至少 850px 宽的表格。

参考来源：用户提供的五张界面图；Material Design 的底部导航和 48dp 触控区域规范；美团商品标准化实践关于分类帮助用户找菜的讨论。具体尺寸是本项目的初始方案，不是行业效果数据。

## 页面结构

底部固定五个入口：点单、冰箱、菜篮子、周菜单、菜谱。左侧栏用于当前页面内的分类，不承担主导航。设置保留在顶部。首页不显示欢迎横幅、英文口号或重复大标题。

| 页面   | 主内容                                               | 主要操作                                       |
| ------ | ---------------------------------------------------- | ---------------------------------------------- |
| 点单   | 左侧菜品分类，右侧小图单列菜品；菜名、主要食材、用时 | 搜索、详情、加减份数、确认选菜                 |
| 冰箱   | 左侧食材分类，右侧紧凑库存；数量和保存状态优先       | 添加食材、查看或编辑批次；拍照识别作为次级入口 |
| 菜篮子 | 左侧食材分类，右侧采购缺口；必要时展开需求和库存抵扣 | 查看缺口、复制或导出                           |
| 周菜单 | 顶部七天日期条，默认当天；下方早餐、午餐、晚餐       | 切换日期、给餐次添加菜品；另设纵向一周总览     |
| 菜谱   | 默认已有菜谱列表，搜索和分类                         | 新建、导入、详情、编辑；编辑使用独立页         |

点单确认仍按选菜份数更新采购。周菜单独立安排，不增加采购份数。菜谱历史快照、真实日期、离线数据、草稿和同步规则沿用产品需求。热量不进入本次方案。

## 视觉与交互规格

- 手机内容宽度从 360px 验证；左侧分类约 76px，分类按钮至少 52px 高。
- 菜品小图约 64px；行高由内容决定，通常 110–124px。无图使用小尺寸统一占位，不使用大图标。
- 标题 19–22px，菜名 15–16px，辅助文案 12–13px。使用本机中文无衬线字体，保证离线和可读性。
- 米白背景、白色内容、浅暖灰分隔、暖黄主要操作；黄色背景搭配深色文字，不使用浅黄色正文。
- 系统图标约 20–22px，点击区域至少 48px；选中态同时通过背景、字重和标记表达。
- 主内容垂直滚动，分类栏保持可见；超长分类可独立滚动。底部导航与选菜栏预留空间，考虑 Android 上下安全区。
- 搜索优先匹配菜名和食材；详情与加减份数分别操作。切页保留演示选菜，搜索和分类按页面独立保存。
- 已选栏仅在存在选菜或与上次确认不同的时候展示；允许把原已确认清单清空后再次确认。
- 菜品列表不强制单行截断长菜名；窄屏和字体放大时允许行高增长。减少动效设置生效。

## 第一版原型

入口：`prototypes/mobile.html`，可直接用桌面浏览器打开；或启动 `npm run dev` 后访问 `http://127.0.0.1:5173/prototypes/mobile.html`。宽屏显示手机预览框和说明，手机只显示应用界面。资源全部在本地，无需联网加载图片或字体。

原型文件独立于 React 正式入口，不进入 Vite 默认构建，也不会写入 SQLite、localStorage、业务状态或调用 AI/WebDAV。刷新重置演示数据。目的是审阅界面和交互，不是功能交付或 APK。

可操作：五页切换、分类与搜索、查看菜谱、加减份数、确认选菜、基于演示食材计算采购缺口、复制采购文字、按日期查看三餐、添加/移除演示餐次、添加演示库存、新建简要演示菜谱。

示意边界：库存为单批次演示；录入表单是精简演示；设置、AI 导入明确提示尚未接入；未接通菜谱编辑、历史周复制、完整周视图、真实图片上传、导出文件和原生返回栈。演示菜单固定为 2026-09-14 至 2026-09-20，用于视觉评审，不冒充当前用户的真实菜单。

## 正式落地顺序与验收

1. 视觉验收后先改 App.jsx、styles.css 和 Sidebar.jsx，完成紧凑顶栏、底部导航、分类和点单列表。
2. 再适配库存和采购列表，最后接入按日周菜单、菜谱管理与独立编辑页。
3. 更新产品需求、开发规划与设计逻辑，标明提案中最终被采用的部分。
4. 验证 360/390/430px、横屏和字体放大：首屏可见分类与菜品；无页面横向溢出；加减按钮不遮挡菜名；底部不遮住最后一行；键盘弹出后表单可操作。
5. 复用既有业务测试并补充导航、筛选、份数确认、快照和日期回归。执行 build → cap sync → Android 构建，再做 APK 真机验收。

本次仅独立原型，因此不更改正式应用、同步 Android 资源或重新生成 APK。原型验证脚本为 `tests/prototype_ui.py`；验收截图输出到 `.android-tools/prototype-preview/`，作为交付预览保留，无测试镜像或安装依赖。

## 本轮验证结果

2026-09-18：Python Playwright 使用工作区已有 Chromium，通过五页切换、分类与搜索、详情与 Esc 关闭、加减份数、确认后库存抵扣、确认空清单、按日期添加/移除餐次、演示库存和菜谱录入、刷新重置及本地图片加载检查。360×800、390×844、430×932 与 844×390 下五页均无水平溢出；点单页字体放大 30% 无水平溢出。未捕获 JavaScript 页面异常。

已人工查看点单与周菜单截图。此结论仅适用于浏览器原型；Android WebView、安全区、真实软键盘、系统字体缩放和原生返回行为尚未真机验证。
