## 目标与基准

保留食光现有配色与品牌识别，解决 Android 上大块留白、信息分散、二级页面不统一和入口绕路。沿用 React + Vite + Capacitor，使用系统字体；不引入新的 UI 框架或远程字体。

- [确认菜单条目预览](preview/selection-items.html)：采用 A 紧凑条目方案。完整菜名按内容宽度依次横排、自动换行，短菜名每行约 3 个，空间充足时可更多；不固定列数。单份省略“×1”，多份显示数量，提示说明默认一份。点击条目在下方显示加减操作，再次点击收起；减至 0 后移除，其余条目自动补位。点击区域至少 48px 高，保留现有确认同步和清空采购需求的二次确认。

只以以上最终预览为依据，被放弃的配色探索不属于交付资料。预览为独立 HTML，包含虚构数据和示意交互；不能直接复制其脚本或反复覆盖的 CSS 到正式应用。三页预览并不代表其他页面已完成设计或真机验收。

## 1. 配色及使用位置

最终选择恢复仓库的米白、白色、暖黄色分工，灰绿仅辅助。早前“黄绿按钮”“整屏莫兰迪”“大面积柠檬黄底”均被后续确认替代。

| 角色 | 值 | 用法与来源 |
| --- | --- | --- |
| 页面、顶栏 | `#FAF9F5` | 当前 mobile.css；不再改成偏绿的 `#F5F6EF` |
| 主要内容、输入框 | `#FFFFFF` | 现有列表/面板/输入框；食材和五餐是主内容 |
| 主提交按钮 | 背景 `#F9CC4F`，文字 `#3F361E` | 当前 `.primary`；不以根变量或黄绿色替代 |
| 正文/标题 | `#292C26` / `#2D342E` | 名称依靠字重、字号突出 |
| 辅助文字 | `#666F60`、`#536347` | 灰绿小面积使用，不扩散成大块背景 |
| 底部导航 | 白底；选中图标底 `#F8E9B3` | 只给图标承载区着色，文字区不铺色 |
| 日期选中 | `#F5D779` / `#35422E` | 当前周菜单选择色 |
| 分类 | 区域 `#F0F1E9`、选中白底、标记 `#BB9229` | 沿用现有颜色；预览紧凑横排属于新布局 |
| 通用边框 | `#E9EBE3` | 用于中性细边界 |

新增的局部设计：

- 输入框边框 `#DDD3B9`，白底；轻阴影 `0 2px 3px #50462E0C, 0 5px 12px #50462E09`。名称字段可用 2px 暖金侧边 `#CBB474`，其他字段不全部加粗侧边。
- 悬停边框 `#C5AF78`；聚焦描边 2px `#B59B54`、外偏移 2px；不得取消键盘焦点可见性。错误态优先于普通边框，增加文字说明而非仅变色。
- 搜索框同样有轻微边界与阴影；移动端不用依赖 hover 的交互。
- 主要列表白底、细边框与极轻阴影；辅助营养区采用 `#F7F6F0`、边框 `#E4E0D2`，不使用绿色铺底。
- 标题可用窄暖金标记，配合分隔线和间距划分区域；不能给所有内容加粗框或同等阴影。
- 原有灰绿聚焦与其他控件，在改动范围内统一到同一套明确规则，避免相邻输入框不同。保留减少动画设置。

以上是用户确认的视觉基准，不代表已完成对比度审查。正式实现时校验普通文字可读性、错误状态及禁用态，必要调整限于满足可读性，并记录偏差。

## 2. 信息层级与通用行为

1. 页名与主要操作：简短明确，顶栏“添加”等操作沿用透明底文字按钮，不给每个动作都套主按钮。
2. 主内容：食材列表、菜名、餐次表，白底、较清晰的边界；名称系统字体半粗体，通常 16–17px，辅助信息 12–14px，随系统字号缩放。
3. 辅助内容：筛选、营养、说明，降低底色强度和字重；风险提示单独强调。

间距优先 4/8 的倍数，标题、标签和区域之间有分组关系。点击区域尽量达到 Android 48dp，不通过缩小触摸范围换取紧凑。预览中的小字号与部分小标签必须在正式实现中检查，不能机械照抄。

所有正文遵循系统字体与字体缩放。长名称优先完整显示，必要时换行；大字体、软键盘和内容增多时允许纵向滚动。主操作不得被底部导航或键盘遮挡，不引入页面横向溢出。

## 3. 页面呈现方式

| 独立全屏页 | 紧凑底部面板 |
| --- | --- |
| 新建/编辑菜谱、图文识别、正文识别、设置 | 添加食材、餐次编辑、确认点单、导出选项 |

返回先收起键盘，再关闭顶层面板，再回来源页。设置配置完成后返回发起识别的任务，不能再要求用户选择识别类型。保留既有草稿、错误恢复和发送前确认规则。

## 4. 冰箱与识别核对

- 行结构：名称 → 分类 → 数量及单位 → 期限状态。名称优先，占据可伸缩空间；常规名称尽量单行，大字体或长名可换行。
- 点击库存行打开该批次的底部编辑面板；避免一行内常驻完整表单。识别核对复用同一视觉语言，增加勾选与批量保存，点行按需展开该项字段；部分保存及草稿恢复不能退化。
- 冰箱仅保留“拍照识别”，直接唤起相机；不再先选拍照/小票，不跳设置重复选择。照片确认发送后识别，小票属于可识别的图片内容。
- 过期优先、临期其次；同等级暂沿原顺序稳定展示。自动删除不在范围内。
- 过期：浅红底 `#FFF0ED`、红侧边 `#BD493D`、红色标签 `#B9473B`＋白字“过期·勿食用”。
- 临期：浅黄底 `#FFF7DF`、侧边 `#B98021`、标签 `#F2D27D`＋深色字，明确剩余时间及尽快食用。
- 正常：白底，绿色状态文字 `#588443`，不与风险行同等强调。
- 未知：明确显示“保存期待补充”，允许直接入库及后续补填，不使用正常状态标记。包装标示期限或手动值优先；修改保存方式提示重新估算，不静默覆盖。
- 临期采用分段提醒：总保存期 ≤3 天时提前 1 天，4–7 天提前 2 天，超过 7 天提前 3 天；具体保存期限另按可靠来源核验，阈值不代表食物安全保证。
- 风险摘要同时包含图标和文字，说明过期清理及临期数量；无风险时不展示警告。未知期限与保存规则的具体计算由 P4 完成，不能根据示例数字推导规则。

添加食材面板：名称整行；数量/单位、分类/保存方式、入库日期/参考保存天数成对排列；底部主提交按钮。期限为参考或未知时明确说明并允许修改。软键盘出现时可滚动、按钮可达；不为一屏而隐藏字段。保存失败保留输入。

## 5. 五餐菜单

- slogan 固定为 **“一饭一饮 三餐四季”**，不替换为其他标语。
- 餐次顺序：早餐、午餐、下午茶、晚餐、夜宵。
- 单日采用五行紧凑表格，每行左侧为餐次，右侧直接显示完整菜名与份数，不只展示餐次入口或菜品数量。
- 常规一屏验收：早餐 2 道、午餐 3 道、下午茶 1 道、晚餐 3 道、夜宵 1 道，共 10 道；390×844 与 360×800 CSS 视口、默认字号、键盘关闭时五餐菜名应在首屏内可见。更小屏幕、长菜名或放大字号允许滚动，不能裁字。
- 点击餐次打开底部编辑面板，在其中添加、调整份数、移除；主表不堆编辑按钮。空餐次提供可理解的添加提示。
- 一周总览七天纵向排列，每天复用同一五餐表格，允许上下滚动。
- 日期切换、历史复制、独立快照和采购规则不变；新增餐次不能覆盖旧三餐 key。

## 6. 默认展开的预计营养

- 紧接五餐表格下方展示，默认展开，不用“查看汇总”作为唯一入口。
- 单日视图跟随选中日期展示“当日预计营养”；本周汇总另有明确口径，不能把日值标成本周值。
- 指标：能量 kcal、蛋白质 g、脂肪 g、碳水化合物 g、膳食纤维 g；紧凑两行排列，单位紧邻数值。
- 常驻“菜单预计营养，非实际摄入”。不完整显示“部分估算”及缺失项说明；未知显示“—”，不能用零替代。
- 来源区分本地参考计算与 AI 补充估算；本地缺失时提供主动估算入口，发送前确认，保存结果供离线查看。拒绝或失败不影响查看已有数据。
- 五餐可见性优先；营养允许自然滚动，不为把所有内容挤进首屏而缩小文字。
- 预览的 1,860 kcal 等数据是虚构排版样本，不能进入生产数据或被当作营养算法验证。

## 7. 周回顾与提醒设置

- 标题“本周菜单营养回顾”，显示周一至周日起止日期，包含已安排的周日晚餐和夜宵，给出下周建议；跨周补看显示原目标周日期，不能误标为打开时的本周。
- 默认周日 20:00，两个渠道共用可修改的星期和时间，分别提供开关，不展示独立时间或“沿用另一渠道”选项。
- 前台只显示应用内提醒；后台或关闭时发送系统通知，均遵循对应开关。返回应用仍未查看时，保留一条非弹窗提示，不打断编辑。
- 查看该周营养回顾即停止该周提醒并清理通知，无需生成 AI 报告；生成 AI 报告仍需另行确认发送。
- 本节为本轮新增确认的界面行为，现有三页预览尚未演示提醒设置，不能据此声称预览或真机已验收该功能。

## 8. 验证与现有证据

预览已检查桌面三页并排、390/320 宽度无页面横向溢出、搜索和分类、表单关闭/提交、五项营养默认呈现、无 JavaScript 页面异常。样式核对曾在浏览器加载仓库 CSS，比较 9 项组件颜色；之后的暖金边框、阴影与分区是用户明确接受的新增设计，不宣称所有视觉参数与仓库完全相同。

日志：`.android-tools/color-research/preview-check.log`。尚未完成正式 React 接入、Android 系统字体和键盘、真机外观及已安装旧版的比对，不能标记为应用验收通过。

实现后逐页检查：点单、冰箱、菜篮子、周菜单、菜谱、设置，以及对应二级页面、确认框、空/加载/错误状态；本规格的颜色与层级规则全局复用，不能只改预览的三个场景。

## 实现核对

2026-09-21 预览一致性补修：此前“已接入”仅证明功能存在，冰箱曾混用横排与旧纵栏样式，周菜单也未完整落实预览结构。现补齐冰箱搜索、摘要、横向分类、连续库存行和风险标签；周菜单按日期范围、日期条、标语与道数、五餐标签表排列；识别库存采用同行勾选与折叠字段；共用搜索框统一暖金边界。旧截图和通过记录不能作为此次修复前的视觉一致性证明。

正式业务保留的差异：冰箱期限筛选位于分类与列表之间，七类可横向滚动；真实风险摘要按实际批次展示。周菜单点击日期范围展开翻周/日期输入，历史和营养回顾在表格与营养区之后；顶部“安排菜品”打开可选择餐次的编辑面板。单位保留自由输入，保存期依据、营养覆盖率和来源说明保留，不复制预览示例数据。最终生产构建与真机验收日志见 `.android-tools/layout-fix/`；截图已核验并按用户要求逐个清理。修复包已在 OPPO PGAM10 覆盖安装，当前系统字体/1.15 倍字号、真实键盘及返回通过；其他系统字号档位未验证。≤374px 的识别核对行允许名称独立一行，分类、数量和期限放下一行，避免分类逐字换行。

正式界面已接入上述系统字体、库存字段、五餐与营养布局。菜谱编辑的营养工具默认收起，单日营养仍默认展开；提醒设置为第四个设置页。数据来源与覆盖率显示真实值，未采用预览示例数字。浏览器大小屏、放大字体和键盘压缩验证已完成；Android 系统字体/权限/通知仍待设备验证。


## 2026-09-22 营养回顾层级调整

- 设置导航保持单行，空间不足时横向滑动；切换后选中项进入可见区域。
- 周菜单提供独立营养回顾卡片入口，主页面突出下一周建议和默认展开的每日概览，周合计折叠展示。
- 日期始终对应当前回顾覆盖周的周一至周日，共 7 天；点击切换单日详情，窄屏横向滑动，不固定为上周、不截掉周末。下周建议对应目标周之后的一周。
- 保留“菜单预计营养，非实际摄入”和简短的部分估算状态；不将未知当零或据缺失数据判断营养不足。
- AI 建议经用户确认后生成，正文以简短回顾和 1–2 条可执行建议为主，不平铺全部指标及缺失清单。保存结果可离线查看，菜单变化时标记待更新，取消或失败保留旧建议。
- “高级计算”作为独立次级页面，集中承载重算、逐道克重和营养补充、缺失项、参考来源。返回保持所选日期，计算更新仍写入目标周快照。
- 本次不新增实际摄入记录、个人营养目标或饮食处方，不改采购计算和历史快照规则。
